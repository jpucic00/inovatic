# Inovatic Project

Website for Udruga za robotiku "Inovatic" (Robotics Association), Split, Croatia — operating as two separated city tenants since 2026: Split and Šibenik (Trokut inkubator). Teaches kids ages 6-14 STEM/robotics through LEGO Spike courses (SLR 1-4).

## Tech Stack
Next.js 15 (App Router) + TypeScript + Tailwind v4 + shadcn/ui + Prisma + PostgreSQL (Neon) + Auth.js v5 + Cloudinary (EU) + Resend + React Email + Zod + BlockNote (admin editor only) + Playwright + Vitest (unit + integration tiers)

## Project Structure
- Route groups: `(public)`, `(admin)`, `(teacher)`, `(portal)`, `(auth)`
- Server Actions in `src/actions/` (admin actions in `src/actions/admin/`)
- Zod validators in `src/lib/validators/` (admin in `src/lib/validators/admin/`)
- shadcn/ui components in `src/components/ui/`
- Emails in `emails/` (React Email templates)

## Conventions
- Server Actions for all mutations (no REST API)
- Server Components for SEO-critical public pages
- Croatian locale: date format `dd.MM.yyyy.`, currency EUR, primary language Croatian
- Auth guards: `requireAdmin()`, `requireAdminCtx()` (returns `{ session, city }`), `requireTeacher()`, `requireStudent()` from `src/lib/auth-guard.ts` (`requireAuth` is module-private and fails closed on a session without a `city` claim)
- Roles: ADMIN, TEACHER, STUDENT (future: PARENT)
- Inquiry status flow: NEW -> ACCOUNT_CREATED (or DECLINED at any point)
- Enrollment workflow: Public inquiry -> Admin reviews -> Creates student account + enrollment
- **Radionica CRUD lives on `/admin/programi`** (create + edit + delete), with the same `<CourseFormDialog>` behind "Nova radionica" and "Uredi"; the Uredi trigger repeats in the `/admin/programi/[courseId]` header. `updateCourse` edits title/description/age range/price only and **never regenerates the slug** — `/radionice/<slug>` is the link admins copy and send to parents. Standard SLR programs are refused by the action and show no Uredi button (their copy is shared catalog content). `price` is genuinely optional: `createCourseSchema` preprocesses `''`/`null` to `undefined` so a blank input stores NULL instead of tripping `.positive()`.
- **A radionica termin is offered only until the day it starts.** `isRadionicaOpenForSignup` (`src/lib/session-dates.ts`) keeps a group in the public feed while `dateStart > today` on the **Europe/Zagreb** calendar day; from midnight of its own start date onward `toActiveGroup` drops it, which covers "already running" and "long over" in one rule. A parent's inquiry still has to be read and turned into an account by an admin, so a workshop that has begun is not something they can join. A group with **both date bounds blank** (the admin form permits it) has no start to compare against and stays bookable — missing data must not silently retire a termin. `submitInquiry` re-checks the same rule and answers `code: 'TERMIN_CLOSED'` with a refreshed feed, so a tab left open across the start date cannot post the termin it still has rendered. Deliberately **public-only**: admin flows (add-enrollment, create-account, send-schedule) still see a running workshop, because placing a child into one mid-way is a decision staff are allowed to make. Standard groups are paced by their module arc and competition groups by their season, so neither expires this way.

## Admin list filters are sticky per tab (2026-08-09)
- **The URL stays the source of truth.** Every admin list keeps its filters in the query string (`/admin/ucenici?search=&courseId=&groupId=&payment=&year=&page=`), and `<Pagination>` already threads them. `sessionStorage` is a *memory*, never a second source — it only fills the URL back in.
- **`src/lib/admin-filter-memory.ts`** stores the last query per `(adminId, listPath)`. Per-tab, so two tabs hold independent filters; dies with the tab; and the **admin id is in the key**, which is what makes a relogin reset — a colleague signing in on the same tab reads a different key, and one of them is in the other city, where a remembered `groupId` would narrow the list to nothing.
- **`<ListFilterMemory listPath chips>`** on each list page does two things: restores **on arrival only**, and records every state including the empty one. The narrow window is the whole trick — a select back to "Svi programi", an empty search, the "Svi" tab and the chip × all land on the bare path, and restoring whenever the query happens to be empty would undo every one of them (the plain-`<Link>` tabs and native GET forms have no way to announce themselves). Recording the empty state is the other half: a list cleared on purpose must still be clear after a reload. The `arrived` ref survives same-route client navigation — that is load-bearing, not an optimization.
- **`<BackToListLink listPath label>`** replaces the hardcoded `href="/admin/ucenici"` back links, which dropped the query. It starts bare and upgrades the href in an effect (the server has no `sessionStorage`; rendering the remembered href directly is a hydration mismatch). Doing it on the *link* rather than letting the list restore afterwards is what keeps the common path free of a flash of unfiltered rows. `StudentDetailView` opts in via `backRemembersFilter` — the teacher panel shares that view and has no filtered list to return to.
- **The "Filter aktivan" bar is not decoration.** A restored filter means a table can open already narrowed without the admin touching anything, and "2 of 40" is indistinguishable from missing data unless something says why. Chips are keyed on the **URL param** so the × removes exactly that one, and `withoutFilterParam` drops `page` alongside it — page 3 of a narrower list is usually past the end.
- **`/admin/grupe` was the worst case and is fixed at the source**: the program chip was React state only, so not even browser Back restored it. `GroupsBoard` now mirrors the selection into `?tab=`, and `resolveGroupFilter` accepts both a filter key (what the board writes) and a course id (what `/admin/programi` links have always sent). `all` is that board's clear, so it lands on the bare path.
- **Never run `prettier` in this repo** — there is no config, so it rewrites every touched file to semicolons + double quotes, against the house style.

## `/admin/ucenici` prati godinu iz sidebara (2026-08-24)
- **Reversal of the 2026-06-25 "Učenici je all-kids" rule.** The list is year-scoped to `getSelectedSchoolYear()` like every other Školska-godina section, the nav item moved into that group, and the in-list Godina dropdown plus `?year=` are gone. One year governs the rows, the "Ponovni upis" flags, the Grupe chips and the Plaćanje badges at once — a badge reporting on a year the table is not showing is the single way this column can lie. Two consequences the owner took deliberately: a child with **no enrollment in the selected year is absent from the list**, and **search is scoped too**, so last year's polaznik is found by switching the year, not by typing harder.
- **The page owns the year; the action must not.** `getStudents` still takes `schoolYear` as a parameter and deliberately does **not** read the cookie — `getSelectedSchoolYear()` needs a request context and four integration files call the action directly. `returningYear` survives only as an override for a caller asking about a year it is not narrowing to; `/admin/ucenici` never passes it, so the list, the flags and the badges cannot name different years.
- **`computeStudentPaymentStatus` takes the year being LOOKED AT, never `computeSchoolYear(now)`** — the same trap `getCourseGradeRules` documents. Through the summer today's date still names the year that is *ending* while every upis being made is for the one starting in September, so keying on today made children who were plainly enrolled read **"Bez upisa"**. That was the reported bug.
- **`NOT_DUE` "Nije dospjelo" (amber) is the third state**: enrolled, but no module or month has come due. Folding it into red "Nije plaćeno" was rejected — in August nothing in the coming year has started, so every child would be red and the debtor filter would hand back the whole roster. **Red keeps meaning "chase this family now"**, which is what it is used for; a radionica is owed from the moment of enrollment and so stays red from day one. Green must not claim a payment nobody made either, which is why "nothing due yet" is not `PAID`.
- **`hasDueItems` / `dueEnrollmentWhere` are the third mirrored pair in `payment-status.ts`** — keep them in sync exactly like `isEnrollmentPending`/`pendingEnrollmentWhere`, since the Plaćanje dropdown and the Plaćanje column are two renderings of one rule. They differ from the pending pair by one thing: pending excludes a settled enrollment, due includes it. **PENDING stays cross-year on purpose** (a debt follows a family) while the PAID/NOT_DUE split is decided *inside* the reference year — last year's paid modules say nothing about whether this year has begun. The filter dropdown builds its options from `PAYMENT_STATUS_LABELS`, so a state cannot be worded one way in the filter and another in the table.

## Ugovor potpisan — the one enrollment mark a teacher may set (2026-08-17)
- **`Enrollment.contractSignedAt` is a nullable timestamp, not a status.** Since accounts are created the moment an admin accepts an upit, a child is in the group and on the roster before the family has committed to anything — "Ugovor potpisan" plus the paid marks are what *actually signed up* means. Additive migration, no backfill.
- **Teachers may see and set it; every paid mark stays scrubbed out of their payload.** Teachers collect the signed contracts at the group, which is the whole reason for the exception. It rides in `baseEnrollmentSelect`, deliberately outside the payment scrub in `buildStudentDetailForTeacher`.
- **A teacher is limited to their OWN groups in the CURRENT school year; an admin is unrestricted.** Same split `teacherMarkingWindow` draws for attendance, and for the same reason: a past year's contract is settled, so marking one now is a correction and corrections are the admin's job. Enforced server-side in `setEnrollmentContractSignedByTeacher` (`src/actions/teacher/contract.ts`) — the enrollment is resolved FIRST and `assertTeacherOwnsGroup` runs against ITS group, never a client-supplied id.
- **The UI must not offer what the server will refuse.** A teacher's student profile lists **every** enrollment the child has (`fetchForTeacher` applies no group filter, and `assertTeacherCanViewStudent` needs only ONE shared group), so it routinely shows colleagues' groups and settled years. `assertTeacherOwnsGroup` **throws `notFound()`**, so a live button there replaced the whole profile with a 404 instead of reaching the toggle's error toast. The teacher page therefore passes `contractEditableGroupIds` and everything outside it renders read-only; `undefined` means unrestricted (admin).
- **The shared write lives in `src/lib/enrollment-contract.ts`, NOT in `src/actions/**`.** `writeContractSigned` was originally exported from `src/actions/admin/payment.ts`, which carries `'use server'` — and **every export from a `'use server'` module is registered as its own callable Server Action**. That published an unguarded mutation taking an arbitrary `enrollmentId`, bypassing both wrappers' checks. Keep shared action logic in a plain module (precedent: `student-assessment-core.ts`, `evaluation-email-cards.ts`, `credentials-email-recipients.ts`). A `'use server'` file should export **only** its actions — check this whenever you factor something out.

## Dolazak se označava kvačicama, a prazno znači prazno (2026-08-24)

- **`initDraft` je pretpostavljao `present: true` za svaki red bez zapisa**, pa je termin koji nitko nije evidentirao izgledao identično spremljenom — puna kolona zelenih „Prisutan" pilula. Zeleno je tvrdilo činjenicu koju nitko nije potvrdio, a `Attendance` red svejedno nije postojao dok se ne pritisne Spremi. **Sada je prazan start**: kvačica označava odluku nastavnika, nikad stanje baze. Pravila su čiste funkcije u `src/lib/attendance-draft.ts` (`initAttendanceDraft`, `isSessionDirty`, `summarizeSession`, `sessionStatus`) — tipovi su strukturni, da lib ne povuče `'use server'` modul.
- **Broj klikova je isti kao prije, ne veći.** Tri-state „Označi sve prisutne" u zaglavlju (nijedan → sve, djelomično → sve, sve → poništi) vraća pun razred na jedan klik; cijeli red je meta klika osim polja bilješke. Bez toga bi prazan start bio čisti regres za najčešći slučaj.
- **Nastavnici na terminu NAMJERNO zadržavaju pretpostavku „prisutan"** (`initTeacherDraft`). Posljedice nisu simetrične: neoznačen nastavnik je izgubljen sat honorara koji se primijeti tek na kraju mjeseca, dok je pretpostavka ovdje obranjiva — to su nastavnici raspoređeni na taj termin. Dobili su kvačice i vlastiti označi-sve, ali ne i prazan start. Sekcija se i dalje prikazuje samo za grupu s 2+ nastavnika; jednog server bookira sam.
- **Prazna kvačica znači dvije različite stvari prije i poslije spremanja**, i zato traka stanja nije ukras: „Nije evidentirano" / „Nespremljene izmjene — N od M označeno" / „Evidentirano · N od M prisutno · spremljeno …". `dirty` se **računa usporedbom s zapisom**, ne prati zastavicom — označiti pa odznačiti mora ostaviti termin čistim, inače banner laže. Bilješke se uspoređuju **trimane**, jer se takve i spremaju (`note.trim() || null`); sirova usporedba je ostavljala termin zauvijek „nespremljenim". Oznaka „Odsutan" na redu se pokazuje **samo kad zapis to kaže i draft se s njim slaže** — neoznačen red koji nije spremljen je neodgovoreno pitanje, ne izostanak.
- **Novi rizik koji prazan start uvodi, i njegova brana:** Spremi s nula označenih bi jednim klikom zapisao cijeli popis kao odsutan. Zato ide kroz `<ConfirmDialog>` (ista doktrina kao oznake plaćanja), `destructive` **samo kad bi pregazio postojeće zapise** — prvi zapis je knjigovodstvo, ne brisanje. Spremi miruje kad se ništa nije promijenilo **a zapisi postoje**; termin bez ijednog zapisa ostaje spremiv, inače sat na koji nitko nije došao ne bi bilo moguće evidentirati. Prazan popis (modul bez upisanih) ne pita ništa — to nije „nitko nije došao".
- **Čip u listi termina pokazuje `—` umjesto `0/8`** kad ništa nije evidentirano: `0/8` se čitalo kao „nitko nije došao", a broji zapise, ne prisutne. `8/8` i dalje znači „sve evidentirano" — to je pitanje na koje ta lista odgovara.
- **`<SessionPanel key={sessionDate}>` je zajednički za obje grane** (standard i flat), koje su prije držale dvije kopije istog state/save koda. Promjena datuma remounta panel, pa draft dolazi iz zapisa tog datuma — nema više resetiranja kroz četiri settera. `AttendanceRecord.recordedAt` dolazi iz postojećeg `updatedAt` (bez migracije) i nosi „spremljeno …".
- **Mobitel je prvorazredan slučaj**: dolazak se upisuje u učionici, a stara tablica se ondje skrolala vodoravno. Redovi su 52px, kvačica 24px (20px od `sm`), bilješka se otvara olovkom umjesto da krade prostor imenu. Ciljevi dodira ≥44px.

## Nijedna oznaka se ne mijenja jednim klikom (`<ConfirmDialog>`, 2026-08-19)
- **Every paid mark and "Ugovor potpisan" asks first, in BOTH directions.** They render as a dense wrapped row of near-identical chips a mis-aimed click apart, and the only trace of a stray mark *or* a stray un-mark is a toast that fades — a family then gets chased for money they paid, or never chased at all. Marking is confirmed as well as un-marking on purpose: the wrong mark is the half that hides, because it looks exactly like a real one for the rest of the year.
- **`<ConfirmDialog>` (`src/components/shared/confirm-dialog.tsx`) is for marks; `globalThis.confirm()` stays for deletes.** The delete buttons name a whole object ("Obrisati materijal X?"), which a browser prompt carries fine. A mark has to name the exact chip **and** the enrollment it belongs to — `groupLabel` is threaded from `student-year-sections.tsx` because a child in two groups has the same module titles in both, and the modal covers the card that was clicked.
- **Controlled by a request object, not a trigger.** One dialog mount per panel, many buttons, each button's closure carrying its own copy and action. The request is deliberately **remembered through the close animation** (Radix keeps the node mounted for the fade), or the last thing an admin sees is a blank box. `destructive: true` is reserved for taking a mark **away** — setting one is ordinary bookkeeping, undoing one throws a date on the floor that nobody can reconstruct. "Odustani" is first in the DOM so it takes the dialog's initial focus and a stray Enter cancels.
- **The year mark's sentence is picked per `ProgramKind` in `yearConfirmCopy`**, because what it sweeps up differs: a radionica's single payable item, a standard program's modules, a competition season's months. Undoing it leaves the per-item marks untouched (`setEnrollmentYearPaid` only clears `fullYearPaidAt`) and the copy says so, since "cijela godina" reads like it would wipe them.

## Pristupni podaci idu kampanjom, ne automatski (CREDENTIALS, 2026-08-17)
- **Creating a student account mails NOTHING.** Neither `createStudentFromInquiry` nor `createStudentManually` sends anything any more; the password stays readable on the student profile, which is the primary early hand-over. Logins leave the building **only** through a `CREDENTIALS` e-mail campaign on `/admin/email`, run once contracts are signed — which makes the send deliberate, auditable per family, and repeatable.
- **One row per child ACCOUNT — the same rule as EVALUATION, for the same reason.** Two siblings on one address get two separate mails; a child in two selected groups still gets one. `parentEmail` is not a family identifier, so not merging makes "another child's password in my inbox" impossible by construction rather than merely checked. `assertCredentialsBelongTo` (`src/lib/credentials-email-recipients.ts`) re-derives ownership from the student's **current** `parentEmail` immediately before each send and **fails closed**; `credentials` is declared **inside** the send loop and `SendJob` has no field that could hold one recipient's content — **do not add one**. The child's name is appended to the subject per recipient.
- **A third selection mode: `sourceStudentIds` ("pojedinačna djeca"), CREDENTIALS-only** (validator-enforced) — it is the only kind whose unit is an account rather than a document or an inbox. A preporuka cohort is refused: it names children, not accounts.
- **Radionica groups are deliberately NOT excluded.** A workshop child gets a real portal account and their login is valid until the end of the school year, so `kindExcludesRadionice` lists `REENROLLMENT` and `EVALUATION` **positively** rather than excluding everything but `CUSTOM`. Excluding them only hid the group from the composer with no error, so the families most likely to be forgotten were the ones the campaign could not reach.
- **Passwords are minted up front, at campaign creation, never in the send loop** — a resumed run would otherwise rotate a password the first run already mailed. Only accounts with `plainPassword: null` are touched (an unusable hash, every workbook-imported account), so nothing is destroyed. **The hashing happens OUTSIDE the transaction** (`mintPasswordsFor` → `persistMintedPasswords`): bcryptjs at cost 12 is ~200 ms per call, and a sequential loop inside Prisma's 5 s interactive-transaction budget blew up at roughly two dozen children — exactly a cohort of imported kids, which is this campaign's primary audience. The write repeats the `plainPassword: null` condition as an `updateMany` so a concurrent `resetStudentPassword` still wins. No `sentKey` — a corrected send must stay repeatable.
- `User.credentialsSentAt` records delivery, is cleared by `resetStudentPassword`, and is deliberately **not backfilled**: null means "not sent by this system", never a guess. `sendStudentCredentialsEmail` still exists but **has no caller** — kept for a possible future single-child send, and knip cannot flag it because two unit tests reference it.

## Polaznički portal traži aktivan program (2026-08-17)
- **"Active" is the CURRENT school year PLUS the NEXT** — `activeSchoolYears()` / `activeEnrollmentWhere()` in `src/lib/enrollment-activity.ts`, the single definition behind the login gate, the token revalidation and every student-facing read. The two forms **must stay mirrored** (a unit test asserts it), same discipline as `isEnrollmentPending`/`pendingEnrollmentWhere`.
- **The next-year arm is not a nicety.** Next year's accounts are created over the summer and the CREDENTIALS campaign runs in the same window, so a current-year-only rule would refuse every child the moment they used the password they had just been mailed. There is deliberately **no grace tail** after 1 September: a child who was not re-enrolled losing access then is the requested behaviour.
- **`authorize()` is the PRIMARY gate**, because it is the only point where **no cookie is ever minted** — it throws `NoActiveProgramError` (code `no_active_program`) and the login form shows a specific Croatian message, deliberately different from the wrong-password copy since the password *was* right. `revalidateTokenClaims` evicts an already-logged-in student within ~60 s; that check sits **inside the same `try`** as the `deletedAt` check so the deliberate **fail-open** covers it — a Neon cold start must never log out the entire student body.
- **`requireActiveStudent()` fails with `notFound()`, NOT `redirect('/portal')`** — `/portal` renders the dashboard for a STUDENT session, so redirecting there loops forever. It checks that the **caller** is active, **not** that the requested group is this year's: an enrolled child looking back at their own previous group is legitimate, and year-filtering the per-group lookups would quietly withdraw the parent-visible evaluation. `/api/download/[materialId]` mirrors it inline (it authorises off a session, not through the guard). **Known gap:** `/api/proxy/elearning` does not yet apply it.

## Probni tjedan (`TrialWeek`, 2026-08-17)
- **One week per `(schoolYear, city)`; every STANDARD group runs its trial on its own `dayOfWeek` inside it.** No FK and nothing stored per group — a calendar week holds exactly one of each weekday, so `computeTrialSession` (`src/lib/session-dates.ts`) derives the date from the group's existing weekday, and holiday-awareness comes free: a holiday on that day **removes** the group's trial rather than moving it. An **absent row is the "no probni sat this year" state** (the `CourseGradeRule` doctrine), which also means the feature is dark until an admin sets a week on `/admin/skolska-godina`.
- **`resolveTrialDateForGroup` is keyed on the GROUP'S own `schoolYear`, never `computeSchoolYear()`** — the same trap `getCourseGradeRules` documents. STANDARD only (`hasDatedModules`): a radionica *is* a one-off trial of its own and the competitive program is invitation-only.
- **The trial is an EXTRA session before module 1 — module 1 keeps its full seven.** `buildStandardAttendance` unshifts a "Probni sat" section **before** `bucketAdhocDates`, or a marked trial would fall into "Ostali termini"; `moduleScheduleId` is null (nothing to bill against) and the whole roster is listed, since the trial predates any per-module enrollment. Marking it writes ordinary `Attendance` **and** `TeacherAttendance`: free for the child, a paid hour for the teacher, so it shows up in Evidencija rada like any other date.
- **The parent does NOT request it on the signup form (removed 2026-08-18, Flux `rgyemhz`).** There is no checkbox, no `checkTrialEligibility` endpoint, and no `Inquiry.wantsTrial`/`trialDate` — staff decide who is new (the "Ponovni upis" marker already tells them) and mail the termin once the probni tjedan is scheduled. The form path was an implementation mistake: it bought nothing the admin did not already know, and it cost an unauthenticated endpoint that confirmed whether a named child had an account, plus two public pages promising a trial that only materialised once a `TrialWeek` row existed. **Everything in the three bullets above stays** — only the parent-facing request path went. The public copy on `/prijava` and `/programi/[slug]` now *describes* what the association does rather than instructing the parent to ask.

## "Ponovni upis" filter on both admin lists (2026-08-17)
- **One badge, two derivations, and they cannot be expressed in each other's terms.** `<ReturningBadge>` (`src/components/admin/returning-badge.tsx` — shared, not under `inquiries/`) marks an upit whose child already has an account (`flagReturningInquiries`, identity matching) *and* a student whose own enrollment history spans years. Both answer "has this family been here before" at two points in the funnel: an inquiry has no enrollments, and a student re-enrolled by an admin has no inquiry. `src/lib/returning-filter.ts` owns the filter vocabulary plus the student rule in **both** forms — `isReturningStudent` (in-memory, feeds the column) and `returningStudentWhere` (Prisma, feeds the filter). Keep them mirrored, same as `isEnrollmentPending`/`pendingEnrollmentWhere`.
- **A student is returning for a school year when enrolled in THAT year and in some earlier one.** Deliberately "any earlier year", not the one immediately before — a child who sat a year out and came back is the returning polaznik this marks. Two enrollments inside one year are one year of attendance, and a *later* year never makes an earlier one returning (an admin planning ahead enrolls into next year while the list still shows this one). Year labels are `YYYY/YYYY`, which is what makes ordering them as strings exact and lets the same rule go into SQL.
- **The reference year is resolved on the PAGE, not in `getStudents`** — the `year` filter if set, else `getSelectedSchoolYear()` — and passed in as `returningYear`, which the result echoes back so the column header, the chip and the flags can never name different years. The action deliberately does **not** read the year cookie: `/admin/ucenici` is not a year-scoped list, and a cookie read there would also break every caller outside a request context (four integration files call `getStudents` directly).
- **Turning the filter on narrows to that year in both directions.** RETURNING and NEW both require enrollment in the reference year, so "izvuci sve ponovne upise ove godine" is one question, not two — and a student enrolled *only* in an earlier or later year is in neither set. "Not returning" must never collapse into "new".
- **On `/admin/upiti` the marker is not a column, so the filter runs in two phases**: flag the whole (year + city + current filters) set with `flagReturningInquiries`, then let the surviving ids narrow the real paginated query — `total` and the page slice then agree. Do **not** rewrite the two-tier matching as a SQL `EXISTS`; `src/lib/student-match.ts` exists so the dedup-on-create path and the display marker cannot drift, and a third copy for one filter would be the drift.
- **PARTY rows drop out of BOTH directions.** A proslava carries no child, so it is never returning — but letting it fall into "Novi upis" would count a birthday party as somebody's first enrollment. An admin who also picks Vrsta: Proslave therefore gets an empty table: the two filters genuinely do not intersect, and silently overriding their type choice would answer a question they did not ask.

## Phase 3 (student portal + teacher panel) conventions
- **Student portal** at `/portal` is gated by `requireStudent()`. Students with exactly ONE active enrollment land directly on that group's current-module materials (no extra click); 2+ → grid of group cards. The **0-enrollment empty state is unreachable through login** since the active-program gate (2026-08-17): `authorize()` refuses the account outright with `no_active_program`, so no cookie is minted and the child never gets as far as the dashboard. The empty state remains only as a fallback for a session whose last enrollment disappears mid-visit, and the behaviour that is actually tested is the refusal (`tests/phase3/21-student-portal-shell.spec.ts`) — it must keep saying *why*, because the password was right and the wrong-credentials copy would send that family resetting a working one.
- **Teacher panel** at `/nastavnik` is gated by `requireTeacher()` (admins pass through for support). Group-scoped routes use `assertTeacherOwnsGroup(groupId)` from `src/lib/teacher-guard.ts` — teachers 404 on colleagues' groups.
- **The teacher's student page goes back to the GROUP it was opened from (2026-08-10)**, not out to "Moje grupe". The roster is the only way in, so it threads `?grupa=<groupId>` onto every student link and `/nastavnik/ucenik/[id]` resolves it via `getStudentGroupContext` — a query param, deliberately, not the admin lists' `sessionStorage` memory: there is no filter state to restore, just one id the linking page already knows. That resolver is the **non-throwing** twin of `assertTeacherOwnsGroup` and requires **both** that the student is enrolled in the group and that the caller may open it (own assignment; same city for an admin), so a stale or hand-edited id costs the back link and nothing else — 404-ing a student profile over a query param, or handing back a link that 404s on click, are both worse than the bug this fixed. No param (direct URL, a revalidated link) still reads "Natrag na moje grupe".
- **"Moje grupe" tabs by school year (2026-08-10)**: `getMyAssignedGroups` returns **every** year (it used to hard-filter `computeSchoolYear()`, which left last year's group unreachable from the panel even though `assertTeacherOwnsGroup` never checked the year), and `<TeacherGroupsBoard>` filters client-side. The tab list is every year the caller has groups in **plus the current year always**, newest first, and **the current year is preselected on every visit** — deliberately state-only: no cookie, no `sessionStorage`, no query param, unlike the admin lists' sticky filters. A teacher opens the panel to teach *this* year; a past year is a lookup, not a place to be left parked. The selector renders even for a single year — it replaces the old page subtitle that named the year, so the list is never year-ambiguous.
- **The same tabs sit on `/admin/nastavnici/[id]`** ("Dodijeljene grupe", `<TeacherAssignmentPanel>`), which listed every year in one flat list. It opens on the **admin's sidebar-selected year** (`getSelectedSchoolYear()`), NOT `computeSchoolYear()` — an admin who switched the section to next year is planning next year's assignments, and every other admin list already follows that cookie. "Dodijeli grupu" is a **dialog with the year first**: pick the školska godina, then a group from that year only (group names repeat across years, and the old single all-years dropdown made a mis-assign easy). The year select lists **every year the city has groups in**, reconstructed with no extra query as `assignableGroups` years ∪ the teacher's assignment years (`getAssignableGroupsForTeacher` returns all city groups *minus this teacher's own*, so the union is exact). A year whose groups are all already his **stays listed and explains itself** ("Sve grupe u … već su dodijeljene ovom nastavniku.") — hiding it reads as a bug, which is exactly how it was first reported. It opens on the **tab being viewed**, falling back to the newest year that still has a free group so it never opens on an empty list. Changing the year clears the picked group (a stale id would otherwise still submit), and a successful assign **switches the panel to the assigned year** — otherwise assigning into a year other than the one on screen reads as "nothing happened". `activeYear` is kept in the tab set so the open tab survives that assign and unassigning a year's last group. The per-row year badge is gone: the active tab names it.
- **Material scope model** (`MaterialScope` enum): MODULE → visible on every group of that course+module; COURSE → visible on every group of that course (standard and radionice); GROUP → visible only in that one ScheduledGroup. Per-group exceptions via `MaterialGroupHide`. No publish/draft — attached = visible. Videos support Cloudinary upload OR an embedded YouTube/Vimeo URL.
- **Attendance** is `(Enrollment, sessionDate)` — no separate `ClassSession`. Teacher marks weekly from the Dolazak tab; admin reads `getStudentAttendance(studentId)` on the student page.
- **Comments** are pure notes in `StudentComment` (the `type`/`moduleId` fields and MODULE_REVIEW were removed 2026-07-11). **Grades** live in `StudentAssessment`: one report card per `(studentId, groupId)` — six nullable `SkillLevel` skills, `opisnaOcjena`, and `recommendationKind` (+`recommendedCourseId` when COURSE). Standard programs only — radionice are never graded (enforced in `src/lib/student-assessment-core.ts`); the admin action additionally requires enrollment membership, the teacher action `assertStudentInGroup`. **Comments stay staff-only — never rendered in `/portal/*`. Grades are parent-visible read-only since 2026-07-25**: `/portal/grupa/[groupId]/evaluacija` renders the report card via `getMyAssessmentForGroup` (`src/actions/student/assessment.ts` — enrollment lookup is the access gate, ids resolved to labels, an all-blank row reads as "not graded yet") and `<AssessmentReadonly>`; the editable staff card and the portal card share `SKILL_LEVEL_BADGE_CLASS` so levels read the same in both. The Evaluacija pill on the portal materials screen is hidden for radionice. Teachers can delete only their own comments; admins delete anything *within their city* (`canDeleteComment` in `src/lib/teacher-guard.ts`; both delete actions resolve the comment's group city first).
- **Gallery** (`GalleryImage` model, added 2026-05-07): per-group image bucket, scoped by `(scheduledGroupId, moduleId?)`. Standard programs require `moduleId`; radionice (`Course.isCustom = true`) require `moduleId IS NULL`. Validation lives in the server action (`src/actions/gallery/crud.ts`), not in a DB CHECK. Teacher `Galerija` tab on `/nastavnik/grupa/[id]`, student read-only view at `/portal/grupa/[id]/galerija`, admin `<GroupGalleryPanel>` on `/admin/grupe/[id]`. Upload route `/api/upload/gallery`: image-only (jpeg/png/webp/gif), **10 MB cap to match Cloudinary free-plan image limit**, ADMIN+TEACHER. `publicId` stored on the row; cleanup via `destroyCloudinaryAssetsByPublicId` in `src/lib/cloudinary-cleanup.ts`. Lightbox = `yet-another-react-lightbox` v3.29 + `Download` plugin (already installed for article galleries — reuse, don't reinvent).
- **Login lives AT `/portal` (2026-08-06)** — there is no standalone sign-in route since the wording change freed `/prijava` for the public signup form. `(portal)/portal/page.tsx` branches: guest (or a fail-closed session without a `city` claim) → `<LoginScreen>` rendered in place; ADMIN → `/admin`; TEACHER → `/nastavnik`; STUDENT → dashboard. Every auth redirect (middleware, `auth-guard`, `teacher-guard`, `logoutAction`, `pages.signIn`) targets `/portal`, so `/portal` itself must never bounce a guest — it is the loop terminator. Middleware therefore exempts the exact `/portal` path and the `(portal)` layout no longer gates (chrome renders only for a city-bearing STUDENT; access control lives in the student actions' own `requireStudent()`).
- **Role-based login redirect**: `src/actions/login.ts` routes ADMIN → `/admin`, TEACHER → `/nastavnik`, STUDENT → `/portal`. A **dual-role admin** (ADMIN with ≥1 `TeacherAssignment`, e.g. Slavica) instead gets a panel choice on `/portal` (`showTeacherPanel` in the action result → Administracija / Nastavnički panel buttons in `login-form.tsx`); the teacher header shows an "Administracija" link back to `/admin` for admins, mirroring the admin sidebar's "Nastavnički panel" shortcut. The E2E `loginWithEmail` helper auto-picks Administracija when the choice appears. The flag gates **only the landing page** — the sidebar shortcut is unconditional (below), so a non-teaching admin still reaches `/nastavnik` in one click.

## Teacher attendance + work report (payout hours, 2026-07-26)
- **Teachers have attendance just like students.** `TeacherAttendance` is keyed `(userId, scheduledGroupId, sessionDate)` and deliberately **not** on `TeacherAssignment`: rows survive unassignment, a stand-in covering one session, and any later reshuffle, so a month already worked can never be rewritten. Nothing pins an assignment — removing a teacher from a group and `deleteTeacher` are both unrestricted again.
- **A teacher may only record the current calendar month, up to today** (`teacherMarkingWindow`, `src/lib/attendance-window.ts`, Europe/Zagreb-anchored like `monthWindows`). No future dates — those were self-creditable payout hours — and no earlier month, which deliberately forces attendance to be kept current on the group rather than filled in at month end. **Admins are unrestricted**: `src/actions/admin/attendance.ts` is the correction path, so a genuinely missed session never becomes unrecordable. `getGroupAttendance` returns `markingWindow` (null for an admin) so the UI degrades honestly — out-of-window dates stay viewable, but Save is replaced by the reason and the roster goes read-only.
- **A retroactive holiday deletes BOTH tables' rows** for that date, city-filtered, in one transaction — otherwise a cancelled class stayed billed. `TeacherAttendance.scheduledGroupId` is `onDelete: Restrict`, and `deleteGroup`/`deleteCourse` block on it explicitly: these rows are payout evidence.
- **Hours count only from a present `TeacherAttendance` row** — never from who typed the student attendance in. Session length is the group's `endTime − startTime` (60/90 min; a group without usable times lists its sessions but contributes 0 h).
- **Written in the same transaction as the student roster** (`bulkMarkSession`): a group with **one** assigned teacher books that teacher automatically — no interaction, no UI. With **2+** assigned teachers the Dolazak tab shows a *Nastavnici na terminu* section (all pre-marked present) and whoever marks the session says who actually taught. `resolveTeacherEntries` drops any userId that isn't assigned to the group, so a stand-in must be assigned before they can be booked; if nobody is marked on a multi-teacher group, nobody is booked.
- **"Evidencija rada" card on `/admin/nastavnici/[id]`** — the last `REPORT_MONTH_COUNT` (12) calendar months, newest first, the basis for hourly payout. `getTeacherWorkReport` (`src/actions/admin/teacher-work.ts`) queries by teacher (not by current assignments) and hands the rows to the pure `src/lib/teacher-work-report.ts`. Every requested month is emitted even when nothing was worked, so the card always renders a full year; the card itself is a **server component** and each month is a native `<details>`, so a year of session chips costs no client JS. The "hours only, no money" rule was reversed on 2026-08-10 (below).
- **`User.hourlyRateCents` prices the report — one CURRENT rate, no history (2026-08-10).** Integer cents, not a `Float` like `Course.price`: the figure is multiplied by fractional hours and summed, and the per-group subtotals an admin reads must add up to the month total exactly — so a group amount is `round(minutes × rate / 60)` and a month is the **sum of its group amounts**. There is deliberately **no six-month total** (documented on `TeacherWorkReport` itself) — nobody pays out a half-year sum, and one above the months made the current month, the one actually being settled, read as a detail of it. `null` rate ⇒ every `amountCents` is `null` (rendered `—`), never `0`: "no rate set" and "works for free" are different, and only the first hides the money. Changing the rate **re-prices every month in the window, including ones already paid** — the owner chose that over a dated rate table, and the card says so in as many words. If freezing is ever wanted, the additive path is `TeacherHourlyRate (userId, validFrom)` resolved per session date. Set via `updateTeacherHourlyRate` + `<TeacherHourlyRateDialog>`; a **blank input clears** the rate (the validator preprocesses `''` → `null`, accepts `12,50` and `12.50`, and rejects garbage rather than silently wiping a stored rate). Admin-only: the column has exactly one reader, and it must never be selected into a teacher- or student-facing payload.
- **Month boundaries are Europe/Zagreb-anchored** (`recentMonthWindows`), not server-UTC — `sessionDate` is `@db.Date`, so the derived bounds compare exactly.
- **A teaching ADMIN (Slavica) is staff for this section**: `getTeachers`/`getTeacher` accept `role: ADMIN` with ≥1 `TeacherAssignment` **or** ≥1 `TeacherAttendance` (her report outlives the assignment), the row gets an `Administrator` badge, and the TEACHER-only actions (edit, credentials, delete) are hidden on her page. A non-teaching admin never appears.
- The `teacher_attendance` migration **backfills** existing sessions once, replaying the old authorship rule (recorder if assigned, else the group's sole teacher), so months already worked kept their hours.

## Standard SLR ladder (`Uvod` split out of SLR 1, 2026-07-29)
- **`src/lib/courses-data.ts` is the source of truth for the whole standard catalog** — copy, ages, prices, modules, images and array order. The DB is derived from it: `seedStandardPrograms()` in `prisma/seed.ts` upserts by slug (modules by title) and **`npm run db:seed:programs`** applies it to a live DB without touching groups, enrollments or materials. Unlike `seedCompetitionProgram` it deliberately **overwrites** existing rows — `updateCourse` refuses to edit STANDARD programs (`isEditableCourse`), so there is never admin-authored copy here to clobber, and that overwrite is what carries a correction like "SLR 1 is 7–8, not 6–8" through to production.
- **`CourseLevel.UVOD` is a rung before the ladder, not on it.** `Uvod u Svijet LEGO robotike` (`slug: uvod-u-svijet-lego-robotike`, WeDo 2.0, 5–6 g.) is what predškolci do the year before SLR 1. The four SLR levels are deliberately **not** renumbered — each one's name *is* its level, so `courseLevelLabel()` gives the intro program `Pripremna razina` and keeps SLR N on `Razina N od 4`. `sortOrder` is the array index (Uvod 0, SLR 1–4 at 1–4), clear of the competition program (5) and radionice (99). Its card `badge` is **`0`, not `U`** (changed 2026-08-09) — same reasoning: a `0` puts the intro program before SLR 1 rather than beside it. `/programi` pads numeric badges to two digits, so that column reads 00–04, while the homepage square and the reel show a bare `0`.
- **Ages: Uvod 5–6 (predškolci), SLR 1 7–8 (1.–2. r.), SLR 2 9–10 (3.–4. r.), SLR 3 11–12 (5.–6. r.), SLR 4 13–14 (7.–8. r.)** — `GRADE_TO_LEVEL` (`src/lib/inquiry-availability.ts`) maps `predskolci` to `UVOD`; every other grade is unchanged. A unit test asserts each subtitle's stated range matches its own `ageMin`/`ageMax`, because those two drifted apart on SLR 4 before this split.
- **The split is additive — no enrollment moves.** Predškolci already sitting in an SLR 1 group finish the year there; the migration only adds the enum value.
- A new program is not done until its images exist at `public/images/courses/<slug>/` (`cover.webp` + `hero-bg.webp` 1920×1080, `hero-robot.webp` transparent cut-out, `module-1..4.jpg`) and it has a `badge` — the program cards render `course.badge`, since a title that does not end in its own number has nothing to slice.
- **Module images must ship at 4:3 with the model inside the middle ~88% of the width.** `<CourseModuleAccordion>` `object-cover`s each one into two boxes — a `h-12 w-16` desktop thumbnail and an `aspect-[4/3]` mobile body — and **both are 4:3 so there is nothing to crop**. The thumbnail was `64×52` (1.23) until 2026-07-30 and silently ate 7.7% of *every* program's width; if you retune it, keep it 4:3. There is deliberately **no per-module focal point**: the fix is always the canvas, not a CSS nudge, because these are flat-background LEGO product renders whose subject measured dead-centre (cx/cy ≈ 50%) in every file, and a focal point can only choose which end of the robot gets cut.
- Off-ratio art is repaired by **padding the canvas on its own background colour — never rescale or crop**. Done 2026-07-30 for the Uvod set (shipped at 1.47/1.33/1.06/0.92 on `#f8f8f8`) plus `slr-1/module-2` and `slr-4/module-4` (1.50, on `#ffffff`), which the 4:3 thumbnail would otherwise have clipped. `slr-1/module-{1,3,4}` are still 1.27–1.31 but carry enough whitespace that the ≤2.5% crop lands in background only — left untouched. Verify with a subject-bbox measurement, not by eye.

## Razred → program rule is editable per city + year (`CourseGradeRule`, 2026-08-10)
- **`GRADE_TO_LEVEL` (`src/lib/inquiry-availability.ts`) is the DEFAULT ladder, not the last word.** A `CourseGradeRule` row keyed `(courseId, schoolYear, city)` — sibling of `CourseEnrollmentWindow` and `CourseSeason` — replaces it for that one program. Šibenik launched SLR 4 a year after the rest of the ladder, so its 7. and 8. razred are pointed at SLR 3 while Split keeps the default.
- **Absent row = default; `grades: []` = offered to nobody.** That distinction is the whole model — `programAcceptsGrade` reads `if (override) return override.includes(grade)`, and an empty array is truthy on purpose. Never "simplify" it to `override?.length ? … : default`, which hands a deliberately retired program straight back to the ladder.
- **Overlap is intentional.** Two programs may both claim 8. razred; `programsForSelection` returns both and Step 3 already renders one optgroup per program. The rule is *not* a function from razred to program, and nothing enforces uniqueness.
- **Only STANDARD programs have a rule.** `hasDatedModules` is the gate in three places that must agree: `programsForSelection`, the action's `assertGradeRuleTarget`, and whether the editor card renders. Radionice reach signup through `/radionice/<slug>` and the competitive program through its invitation link — both bypass razred narrowing via `preselectedCourseId`, so a rule there would be dead data.
- **`getCourseGradeRules(city)` reads each program's rule for the year its OWN open enrollment window names — not `computeSchoolYear()`.** Upisi for the next school year open during the summer, while today's date still names the year that is ending; keying on "today" would silently ignore the setup the admin did under the year they are actually enrolling for. Same open-window set `loadPrograms` gates groups on, so rule and termini can never belong to different years.
- **`submitInquiry` must resolve the same rules for its `isTerminRequired` re-check.** Left on the built-in ladder the guard is wrong in *both* directions in an overriding city: a termin-less payload for 8. razred sails through (the server looks at SLR 4 and finds nothing), and an SLR 4 window opened there demands a termin the form never offered. The `TERMIN_REQUIRED` result therefore ships `gradeRules` alongside `programs` — a form rendered before an admin edit would otherwise be told to pick from a program its dropdown is filtering out, with no way forward but a reload. `/api/group-availability` is deliberately left returning a bare `ActiveProgram[]`.
- Edited on `/admin/programi/[courseId]` (`<CourseGradesEditor>`, checkboxes + "Vrati na zadano", which **deletes** the row rather than writing the defaults into it — that is what keeps the fallback tracking `GRADE_TO_LEVEL`). `/admin/programi` shows each standard program's razredi and warns **"Razredi bez programa: …"** (`uncoveredGrades`) — per-program editing makes stranding a razred easy, and a stranded razred is invisible on the public form.

## Natjecateljski program (competitive track, 2026-07-27)
- **`ProgramKind` (`STANDARD | RADIONICA | COMPETITION`) is the program discriminator** — branch on `Course.kind` through the predicates in `src/lib/program-kind.ts` (`isRadionica`, `isCompetition`, `hasDatedModules`, `hasModules`, `showsAllModules`, `isMonthlyBilled`, `isGradable`, `isEditableCourse`), never on a bare enum comparison. `Course.isCustom` still exists as a column and is kept in sync on write, but **no application code reads it** — it is retained only so a rollback is not lossy.
- **One shared course** (`slug: natjecateljski-program`, `city: null`, `level: null`, `sortOrder: 5`) whose five `CourseModule` rows are the natjecanja: the four from `competitions-data.ts` plus `Pripreme za natjecanja`. Seeded idempotently by `seedCompetitionProgram()` in `prisma/seed.ts`; **`npm run db:seed:competition`** applies it to a live DB without touching anything else (the `db:seed:articles` pattern).
- **Natjecanja are undated.** No `ModuleSchedule`, no module arc, no active module — `getCurrentActiveModuleForGroup` returns null for COMPETITION, and `buildGroupMaterialsView` emits **all five module sections at once**. Which natjecanje a group attends lives in the group NAME and is deliberately not modelled, so the app must never narrow materials for them. Material scopes are unchanged: MODULE = one natjecanje, COURSE = whole program, GROUP = teacher's own extras.
- **`CourseSeason` `(courseId, schoolYear, city)` → `[startDate, endDate]`** replaces module dates. Sessions = `computeSeasonSessions` — **one a week** on the group's `dayOfWeek`, holiday weeks dropped outright with **no session-count target and no make-up**, so two weekdays legitimately finish with different totals. Edited via `<CourseSeasonEditor>` on `/admin/programi/[courseId]`; the school-year planner explicitly skips COMPETITION (it hardcodes 4 modules × 7 sessions and would abort).
- **Monthly fee, not per-module.** `EnrollmentMonth (enrollmentId, periodStart @db.Date)` rows are written up front by `ensureEnrollment` from the **join month** through season end — a child joining in January never owes the autumn. A month becomes owed when `periodStart <= now`, so the 1st-of-month flip needs **no cron**. `upsertCourseSeason` re-syncs on a date edit and **never deletes a paid month**. `isEnrollmentPending`/`pendingEnrollmentWhere` gained a matching COMPETITION arm — the two must stay mirrored. `fullYearPaidAt` still works as a pay-upfront override.
- **Competition kids ARE graded** (report card + parent-visible `/portal` Evaluacija) — only radionice are not (`isGradable`). The report card's "recommended course" dropdown still excludes this program (`level: { not: null }`), offering it as special tracks instead: `COMPETITION_PREP`, `COMPETITION_PROGRAM`, plus the per-team `COMPETITION_FLL` and `COMPETITION_WRO` (a mentor recommends the team a child should join, which the program-level track cannot express). All of them live in `RECOMMENDATION_SPECIALS` — adding one is that entry plus the enum value, and a unit test fails if an enum member has no entry.
- **Signup is invitation-only through `/prijava/<slug>`** — see below. The program is excluded from `getActivePrograms`, so it never reaches `/prijava` or `/api/group-availability`.
- **Its termin dropdown carries a second answer: `NO_SUITABLE_TERMIN_LABEL` ("Ne odgovara mi predloženi termin", `src/lib/inquiry-status.ts`)** — competition termini are few, sent by invitation and negotiable, so a parent who can make none of them must still be able to reply. Picking it writes `Inquiry.noSuitableTermin` and **satisfies `isTerminRequired`** with no group, so it is an answer rather than a skipped question; the admin reads it back in the same "Željeni termin" row on `/admin/upiti/[id]` where a chosen group would show. The two are mutually exclusive — one dropdown produces both, and `inquirySchema` rejects a payload carrying both. **Competition-only, enforced server-side** on the resolved target course (`submitInquiry`), not on which `<option>`s rendered: the flag would otherwise be the way to skip the termin choice on an SLR program or a radionica, where the offered slot is the only thing on the table.

## Per-program signup links (`/prijava/[slug]`, 2026-07-27; moved off `/upisi` 2026-08-06)
- **The whole signup surface moved `/upisi` → `/prijava`** when the wording changed (login simultaneously moved `/prijava` → `/portal`). `/upisi` and `/upisi/:slug` answer permanent 308s in `next.config.ts` — re-enrollment invitations already mailed out carry `/upisi/<slug>` links, so the redirects are load-bearing, never cleanup candidates.
- **One route serves every program.** `/prijava` stays the public, grade-narrowed catalog; `/prijava/<slug>` is the link you send when the program is already decided. It **bypasses the grade→program rule** (`GRADE_TO_LEVEL`) because `programsForSelection` short-circuits on `preselectedCourseId` — that is the whole point: last year's SLR 1 group moves to SLR 2 whatever their razred says. The grade is still captured, it just filters nothing.
- Fed by `getSignupProgram(city, slug)`; it and `getActivePrograms` share one internal `loadPrograms` and differ **only** in the course filter, so window/capacity/holiday logic can never drift. All these pages are `robots: noindex` and absent from `sitemap.ts` (thin duplicates of `/prijava` + `/programi/<slug>`). Radionice keep their own `/radionice/<slug>`.
- Still gated by `CourseEnrollmentWindow`: closing the window renders an "upisi nisu otvoreni" state, so a link already mailed out never has to be retracted.
- **Copyable from `/admin/programi`** on every program row and in the program header, via the shared `<CopyLinkButton path=…>`. The path always comes from **`publicSignupPath(kind, slug)`** (`src/lib/signup-links.ts`) — never `signupPathForSlug` directly, which is `/prijava/<slug>` unconditionally and therefore wrong for a radionica: `/prijava/[slug]` answers `notFound()` for RADIONICA, so the program header used to hand admins a 404 link for workshops.
- **Grades split per form**: `ELEMENTARY_GRADE_VALUES` (predškolci–8) is the default `gradeOptions`; the competition link passes the full `GRADE_VALUES`, which adds `ss1`–`ss4` (`Srednja škola – N. razred`). `Inquiry.childGrade` and every admin view accept all of them; **`submitInquiry` enforces** that a high-school grade only reaches a COMPETITION course (resolved from the group, else `courseId`) — not just which `<option>`s rendered.
- **REENROLLMENT invitations link at their target program**: `buildBulkMessageElement` takes a `signupPath`, and `email-campaign.ts` derives `/prijava/<target-course-slug>` in `previewEmailHtml`, `sendEmailCampaign` and `resumeEmailCampaign` (re-derived, not persisted — same as the schedule boxes).

## City tenancy (two-city separation, added 2026-07)
- **`City` enum (`SPLIT | SIBENIK`) is the tenant boundary.** City-bearing models: `User`, `Location`, `ScheduledGroup` (denormalized from its venue — composite FK `(locationId, city) → Location(id, city)` makes drift impossible), `Inquiry`, `Article`, `CourseEnrollmentWindow`, `ModuleSchedule`, `SchoolYearHoliday`, `Course` (nullable: `null` = shared standard SLR, set = per-city radionica). Everything else derives city transitively via its group/article parent.
- **Every tenant-owned create passes `city` explicitly — there is NO `@default` on any city column.** Forgetting is a tsc/DB error, never a silent SPLIT mis-stamp. City comes from the session (`requireAdminCtx()` for reads, `adminAction` handler ctx for mutations), from the verified parent row (student ← inquiry, group ← venue), or hardcoded `SPLIT` for the party form. Never from client input.
- **Scoping is session-driven, data-level.** `session.user.city` is a JWT claim (60s DB re-check via `revalidateTokenClaims`; a legacy token without the claim refreshes immediately; a prod city flip propagates without re-login). Middleware stays role-only. Id-based mutations use `src/lib/city-guard.ts` asserts — a cross-city id is `notFound()`, indistinguishable from nonexistent. No city switcher, no super-admin; the admin sidebar shows a read-only city chip.
- **Every dropdown/filter feed is city-scoped**: locations, assignable teachers, courses (shared standard + own-city radionice via `city IS NULL OR city = adminCity`), and every group picker (upiti dialogs, add-enrollment, send-schedule). A new tenant-scoped query or feed is not done without a cross-city negative test — per-site tests live in `tests/integration/city-scoping-*.test.ts`; the residual launch-gate matrix is `tests/integration/city-isolation-matrix.test.ts`; the E2E journey is `tests/phase3/40-sibenik-city-journey.spec.ts`.
- **Slavica exception (dual role):** ONE `User` row — role `ADMIN`, city `SIBENIK` — is both the sole Šibenik admin and its only teacher. All teacher-guard/material/gallery ADMIN pass-throughs are city-bound (`group.city === session.user.city`); `getAssignableTeachers` returns same-city TEACHERs + the city's ADMIN. The **"Nastavnički panel" sidebar shortcut is shown to every admin** — `/nastavnik` is a tenant-bound pass-through (`getMyAssignedGroups` returns the admin's whole city, `assertTeacherOwnsGroup` admits any same-city group), so gating the link on a `TeacherAssignment` only hid a page the admin could already open by URL.
- **Deliberately shared — do NOT city-scope:** standard SLR courses (one canonical `/programi/[slug]` page; never duplicate per city), MODULE/COURSE materials + their downloads (shared curriculum; only GROUP-scope downloads check city), `Tag` taxonomy, `SchoolYear` registry, the elearning proxy (role-only). ## Email (transactional — Resend + React Email)
- **Service at `src/lib/email/`** — server actions import typed senders from `@/lib/email` and never touch Resend directly. `client.ts` holds the Resend client + `sendTransactionalEmail` (the `RESEND_API_KEY` no-op gate + the per-city `from`/reply-to identity); `senders.ts`/`index.ts` expose one sender per email, each owning its subject: `sendInquiryConfirmationEmail`, `sendInquiryNotificationEmail`, `sendPartyInquiryConfirmationEmail`, `sendPartyInquiryNotificationEmail`, `sendScheduleOptionsEmail`, `sendStudentCredentialsEmail`, `sendTeacherCredentialsEmail` (`variant: 'new' | 'reset'`), `sendBulkMessageEmail` (admin-authored subject — the one deliberate exception to sender-owns-subject; paired with `renderBulkMessageHtml` for the composer preview, same element builder so preview ≡ sent email).
- **Admin bulk email (`/admin/email`, 2026-07-24)**: two-step wizard, kinds `CUSTOM` (free text in the standard layout, repeatable), `EVALUATION` (report cards — see the section below) and `REENROLLMENT` (invitation with this-year target-program schedule boxes + `/prijava` CTA; idempotent — one invite per parent per `(city, targetCourseId, targetSchoolYear)`, source year deliberately NOT in the key; **enforced by the DB**, not by a pre-flight read: that key is stored as `EmailCampaignRecipient.sentKey` on SENT rows only, under a `(sentKey, parentEmail)` unique index, and the row is claimed *before* the mail goes out. Two guards cover two different overlaps: the unique index blocks a re-invite from an **earlier campaign**, while the claim itself is PENDING-conditioned (`updateMany({ id, status: 'PENDING' })`), making two runs of the **same campaign** per-row exclusive — CUSTOM/EVALUATION rows carry no sentKey, so the status condition is their *only* protection; never weaken it back to a bare id-update). Cohort = source year + ONE of two selection modes (validator-enforced): **by groups** (multi-select grouped by program; REENROLLMENT standard-only, re-enforced server-side) or **by preporuka** (`recommendations` — encoded `encodeRecommendation` values from the full report-card dropdown set (`getRecommendationOptions`: each SLR course + every `RECOMMENDATION_SPECIALS` track); every student of the year whose `StudentAssessment` matches one, group- and program-independent; campaign audit stores display labels in `sourceRecommendations`). The invitation recipient list badges each child's source-year preporuka (labels via `formatRecommendationLabel` in `src/lib/assessment-rubric.ts`; preporuka mode badges both kinds); recipients dedupe by normalized `User.parentEmail` (`src/lib/bulk-email-recipients.ts` handles the legacy `"Name <a@b>"` import residue; never mail `User.email` — always synthetic). Client submits **filters + `excludedParentEmails` only** — the server re-resolves and can only shrink the audience. **The send runs in the background** — the action returns a `campaignId` immediately and the loop continues in the Node process, so the admin can close the tab; the wizard polls `getCampaignProgress`. Every intended recipient is written upfront as `PENDING`, so `/admin/email/[campaignId]` lists the whole cohort from the first second: parent e-mail, child name(s), status (`PENDING`/`SENT`/`FAILED`/`ALREADY_SENT`/`SKIPPED`) and reason. Children whose parent has no usable address are persisted as `SKIPPED` rows **by name** — that is how you answer "which kid didn't get the invitation". A deploy or crash mid-send leaves `PENDING` rows; **Nastavi slanje** finishes exactly those. Sequential loop throttled 600 ms when `RESEND_API_KEY` set (Resend 2 req/s; override with `EMAIL_SEND_THROTTLE_MS`, read per call). Batching was deliberately rejected: Resend's batch endpoint reports errors per batch, not per recipient, which would cost the per-parent delivery status this feature exists to provide. Non-throw counts as sent; `EmailCampaign`+recipient rows power the history table. Actions in `src/actions/admin/email-campaign.ts`, validators `src/lib/validators/admin/email-campaign.ts`, template `emails/bulk-message.tsx`, tests `tests/integration/email-campaigns.test.ts`.
- **Evaluation e-mail campaign (`EVALUATION` kind, 2026-07-30)**: mails parents their child's report card. **One e-mail per CHILD, not per parent inbox** — the single most important thing about this kind, and the opposite of every other campaign. Two siblings on one address get two separate mails, each carrying exactly one card, because the merge key (`parentEmail`) is *not* a family identifier: nothing stops two unrelated children sharing a mistyped or institutional address, and no guard can tell that apart from real siblings. Not merging makes "another family's evaluation in my inbox" impossible by construction instead of merely checked. Three layers back that up: (1) the card list lives on `EmailCampaignRecipient.assessmentIds` — the ROW, never the campaign; (2) `assertCardsBelongTo` (`src/lib/evaluation-email-cards.ts`, pure + unit-tested) re-derives ownership from the student's **current** `parentEmail` immediately before each send and **fails closed** to `FAILED` on any disagreement (address corrected mid-send, card deleted, set mismatch, wrong city) — nothing is sent; (3) `cards` is declared **inside** the send loop and `SendJob` deliberately has no field that could hold one recipient's content, so the classic mail-merge leak has nowhere to live — **do not add one**. The child's name is appended to the admin's subject per recipient (`"<predmet> – Ana Anić"`), which both separates two mails in one inbox and makes a misdirected card obvious to the one person best placed to notice. Cohort = selected groups only (a preporuka names children, not cards — validator-rejected), with **"Odaberi sve grupe"** submitting real ids so the audit snapshot stays complete; competition groups included (their cards render the COMPETITION rubric automatically via `skillCategories`), radionice excluded (never graded). Exclusion is keyed on `EmailRecipient.rowKey` = the card (`excludedAssessmentIds`), **not** the address — excluding by address would silently drop the sibling of every child unchecked. Ungraded and blank-carded children become named `SKIPPED`/`NOT_GRADED` rows, listed in step 2 *before* sending (plus a `12/14 ocijenjeno` readiness counter per group in the tree) and persisted for the record; blankness is the one hard rule (`isBlankAssessment`, shared with the portal so both agree on "graded"), while a partially graded card still sends and is only badged `nepotpuna`. `previewEvaluationEmailForRecipient` renders one real recipient's actual mail through the same guard. No `sentKey` — deliberately repeatable, since a corrected card must be re-sendable. Card template `emails/components/evaluation-card.tsx` (imports the rubric from `src/lib/assessment-rubric.ts` via a **relative** path — `emails/` is outside the `@/*` alias — and needs `SKILL_LEVEL_BADGE_STYLE`, the literal-hex twin of the Tailwind chip classes, because mail clients have no Tailwind).
- **Every public sign-up announces itself to a staff inbox (2026-08-10)** — `sendInquiryNotificationEmail` on `submitInquiry`, `sendPartyInquiryNotificationEmail` on `submitPartyInquiry`, both rendering `emails/inquiry-notification.tsx`. **`replyTo` is the parent**, which is the whole feature: staff triage and answer the family from Outlook without opening `/admin/upiti`. **Routed by `cityInboxEmail(city)`** (`src/lib/email/client.ts`, now the single owner of the Šibenik address and also what gives a bulk campaign its per-city reply-to) — a Šibenik upit must never land in Split's inbox. Proslave are Split-only, so that sender takes no city. Unlike `/stem-edukacija` the upit **is** persisted, so this is a notification and not the record: failure is **swallow-and-log** after the row is committed, and the mail carries an "Otvori upit u aplikaciji" link to `/admin/upiti/<id>`. The "Željeni termin" row is resolved **after** the transaction, from the group (`formatGroupSchedule` — reuse it, a radionica is a date range and not a weekday) or from `NO_SUITABLE_TERMIN_LABEL`; absent means nothing was bookable, which is itself what the reader needs to know. **The "Ponovni upis" marker rides along too (2026-08-17)** — `resolveReturningMarker` runs the very `flagReturningInquiries` the upit list and the dashboard badge use (`studentId: null`, since a brand-new upit has created no student), so the inbox and the app can never disagree about whether a child is already a polaznik; a returning child is enrolled into the next level rather than signed up from scratch, and that decision is made in Outlook. Same two tiers as the badge: a same-city match prints the violet callout, a match living only in the other city collapses to the **masked** `OTHER_CITY` variant ("postojeći polaznik (druga lokacija)" + the escalation line), revealing exactly as much as `/admin/upiti/[id]` does. The label itself is imported from `src/lib/inquiry-status.ts` (relative — `emails/` is outside the `@/*` alias) and repeated in the **preheader**, which is what Outlook shows beside the subject. Field rendering is shared with the STEM notification via `emails/components/notification-field.tsx`, and `showSignature={false}` — a mail *to* the association must not close with the association's own contact card.
- **STEM education inquiry (`/stem-edukacija`, 2026-07-25)**: B2B form for schools/institutions (mentor training, equipment consulting, curriculum work), teased by `<StemEducationSection>` on the homepage between the competitions band and Lokacije. **Deliberately persists nothing** — no `Inquiry` row, nothing in `/admin`: the notification email to `ASSOCIATION_EMAIL` (reply-to = the submitter) IS the record, so its failure is the one surfaced to the visitor while the courtesy confirmation is swallowed-and-logged. Being public, unauthenticated and mail-triggering, it is throttled (5/h per IP, 3/h per e-mail, `src/lib/rate-limit.ts` — in-process, single Railway instance, best-effort by design) behind an off-screen honeypot field that reports success while sending nothing. A sender returning `false` (no `RESEND_API_KEY`) is treated exactly like a throw — otherwise an unset key would destroy the inquiry while telling the visitor it arrived. Action `src/actions/stem-education.ts`, validator `src/lib/validators/stem-education.ts` (its label maps are the single source of truth for both form UI and email body), templates `emails/stem-education-{inquiry,confirmation}.tsx`. Legacy WP slugs `stem-edukacija-za-{mentore,ucitelje}` 308 here.
- **"What happens next" is three-way and shared by the e-mail and the form (2026-08-03)** — `src/lib/inquiry-next-step.ts` owns both the decision (`inquiryNextStep({ scheduledGroupId, noSuitableTermin })` — **named arguments**, because a mis-ordered positional call picked a plausible wrong sentence silently) and the copy (`inquiryNextStepText(step)`). It briefly had two more arms for the probni sat; those went with the form checkbox (`rgyemhz`), and a unit test now asserts **no sentence here mentions the trial** — promising one nobody scheduled is the regression that matters. `submitInquiry` returns `nextStep`, so the form does not derive its own. `TERMIN_CHOSEN` (a group was booked in the dropdown) promises the upis confirmation and deliberately not the upis itself — an admin still has to make the account; `TERMIN_TO_ARRANGE` (the competitive program's `noSuitableTermin` answer) promises to agree on a termin, since those parents have *seen and refused* the list; `TERMIN_TO_OFFER` (nothing was bookable — every radionica termin passed, or the grade has no open group) keeps the original "javit ćemo vam se s dostupnim terminima", and is the default everywhere. Both `submitInquiry` (→ `emails/inquiry-confirmation.tsx`, relative import: `emails/` is outside the `@/*` alias) and `<InquiryForm>`'s success screen read it. **Never re-branch this in one place only** — that sentence was hardcoded twice, and when the form gained its termin dropdown both copies started telling a parent who had just picked a slot that their termin was still coming.
- **Radionica akontacija + ostatak (2026-08-03, expanded to the full payment instruction 2026-08-10)**: the sign-up confirmation carries a "NAPOMENA I UPUTE ZA PLAĆANJE" block with **two payment boxes** — the akontacija (3-day rok) and the ostatak (due 3 days before the ciklus starts) — sharing an IBAN and model, so each box is titled and each states its own Iznos and Opis plaćanja; the two asterisked forfeiture notes close it. **Radionice only**; SLR and natjecateljski confirmations are unchanged. Every figure is **derived, never stored**: `radionicaPaymentPlan` (`src/lib/radionica-deposit.ts`) computes akontacija = 20% of `Course.price`, ostatak = price − akontacija, and the popust variant = ostatak − **a flat 20 €** (drugo dijete / cjelogodišnji polaznik) — a 150 € ciklus reads 30 / 120 (ukupno 150) / 100 (ukupno 130). The popust never touches the akontacija: a family pays the same deposit either way and only settles less at the end. All arithmetic runs in **integer cents off one rounded total**, so the amounts an e-mail states side by side always add up exactly — same reasoning as the teacher payout report. The whole plan is **null** for a price-less radionica and `submitInquiry` also requires a booked `scheduledGroupId` — a free workshop and a "contact me about the next termin" inquiry both get the plain confirmation, because the copy asks for money *za odabrani ciklus*. `discountedRemainder`/`discountedTotal` are **null together** on a workshop cheap enough that the 20 € popust would leave nothing after the deposit (≤ 25 €), and the template then drops just that one line — quoting a negative ostatak is arithmetic, not a policy. **Opis plaćanja is deliberately generic** ("Rezervacija za radionicu…" / "Ostatak uplate za radionicu…" + na ime i prezime djeteta), not the workshop's title: radionice are admin-created with free-text names. The kind is read off the **group's** course, not the submitted `courseId`, so the payment block is not the one thing a crafted payload can switch off. Amounts are emitted as **single template-literal text nodes** — interpolating `{a} EUR` splits them with React's `<!-- -->` separators, which reads fine in a client but makes every assertion on the rendered HTML fail.
- **The sender address follows the city, not an env var (2026-08-17).** `sendTransactionalEmail` takes `city` and uses `cityInboxEmail(city)` as **both** the `from` and the default reply-to, so a Šibenik family is written to by `Inovatic <prijave.sibenik@udruga-inovatic.hr>` and answers it, while Split keeps `prijave@`. `EMAIL_FROM` is **gone** — one global sender put Split's address on every Šibenik mail, and an env var is the wrong shape for a value that varies per email rather than per environment; the Railway var is now inert and can be deleted. Both addresses live on the one verified `udruga-inovatic.hr` Resend domain, so per-city routing needs no extra verification. `city` is **required** on every sender whose email belongs to a tenant (confirmation, credentials, schedule options, bulk campaign, upit notification) for the same reason the city columns have no `@default` — a missing one must be a tsc error, never a silent Split stamp. It is deliberately **absent** on association-level mail (`/stem-edukacija`, Split-only proslave), which falls back to `ASSOCIATION_EMAIL`. Inbound notifications still override reply-to to the submitter, and they now send *from* the same inbox they land in — that is what keeps one office's upiti in one thread. The confirmation's `cityLabel` is **derived from `city`** inside the sender rather than passed alongside it: the grad named in the body and the office in the From line are one fact. No key ⇒ senders silently no-op (local dev/tests).
- **Error policy lives at the call site, not the service** (senders never swallow): inquiry/party confirmations swallow-and-log; student/teacher credentials swallow-and-flag (`emailFailed`/`emailSent` — account is already committed, password stays readable in the UI); schedule-options surfaces a send failure to the admin.
- **Templates** in `emails/*.tsx` (`export default` + `PreviewProps`) share scaffold/footer + the **logo header** via `emails/components/email-layout.tsx`. The logo is Cloudinary-hosted (`branding/inovatic-logo`, `LOGO_URL` in the layout) — not `public/`, since email needs an absolute URL and the apex domain still serves the old WordPress site. **Preview locally: `npm run email`** (react-email dev server on :3001) — dynamic content is driven by each template's `PreviewProps`. See `emails/README.md`. Requires the `react-email` + `@react-email/ui` devDependencies.

## Historical workbook import (2026-07)
`scripts/import-history.ts` + `src/lib/import-history/` load one school year's Excel archive (evaluation sheet + per-group contact tabs named `PON_SLR2_1830-20`) into students/groups/enrollments/paid-marks/report-cards. Groups match existing rows by parsed identity (course+day+start time — tab `1830-20` ≡ prod `18:30-20:00`); missing ones are created under the prod naming convention at Velebitska 32/SPLIT. Imported students get app-convention usernames but **unusable passwords** (no `plainPassword`) — an admin unlocks the account via `resetStudentPassword` ("Generiraj lozinku" on `/admin/ucenici/[id]`), or it self-heals when the child re-enrolls through an inquiry (`findOrCreateStudent` mints credentials on a dedupe hit); unmatched teachers get real TEACHER accounts with `@teacher.inovatic.local` placeholder emails. `PLAĆENO` → `Enrollment.fullYearPaidAt`. Idempotent; errors in the report mean skipped rows, never partial writes of that row. ## Natjecateljski workbook import (2026-07-29)
`scripts/import-competition.ts` + `src/lib/import-competition/` are the sibling importer for the competition archive; the primitives both share (grid/label/column helpers, name+time+skill coercers, the xlsx reader, credential synthesis) live in **`src/lib/import-common/`** — put anything a second importer would need there, not in one of the two.
- **The weekday is the only link between a group tab and its izvješće block.** Group tabs are named `DAN HHMM-HHMM` (`SUB 900-1030`) — no course token, since every group is the one competition course. On the izvješće sheet the block label `NATJECATELJSKI PROGRAM:` holds a **weekday**; on a group tab the *same* label holds the **team** (`PRIPREME ZA NATJECANJA`), which becomes the group's NAME. Two groups on one weekday therefore make their izvješće block unattributable — that is an error, never a guess.
- Group **identity** for match/create is `(dayOfWeek, startTime)` read off the DB columns, never the name: competition groups are named freely (`WRO – srijedom`), and a matched group keeps its stored name.
- The staff block (`MENTOR 1:` / `MENTOR 2:` / `ASISTENT:`) sits above the roster on some tabs and **below it on others**, so every row is scanned for labels and label rows are tested *before* roster rows — otherwise a `MENTOR 1:` value landing in the IME column reads as a child. All three become `TeacherAssignment` rows; the report-card author is the block's own mentor, else mentor 1 → mentor 2 → asistent.
- Report cards write **only** the COMPETITION rubric columns and explicitly null `slaganje`/`programiranje` (mirrors `upsertStudentAssessment`). `parseRecommendation` covers the per-team `FLL`/`WRO` tracks.
- **An implausible DOB drops the date, never the child** (3–25 years old at the start of the school year; the archive holds 1900s). `RODITELJ` and `MAIL` are used interchangeably sheet-by-sheet and either may hold an Outlook `Ime Prezime <email>` paste — the address wins from MAIL, the name from RODITELJ.
- Students match **by name**, not by the app's strict name+DOB rule: these children mostly already exist as DOB-less accounts from the SLR import, and a duplicate account is worse than a missed DOB. A disagreeing stored DOB is reported and kept.
- **Monthly fees**: the season has already been paid, so every `CourseSeason` month is written as an `EnrollmentMonth` already marked paid (and anything left owed is settled). Set the season BEFORE importing or the enrollments get no months.
- **Real-archive quirks the parsers must keep handling** (found via `--inspect`, 2026-07-29): the DOB caption is `DATUM ROD.` — captions are matched with trailing `.`/`:` stripped (`captionKey`), and missing that cost the entire column; label cells are **horizontally merged**, so an unfilled `MENTOR 2:` reads its own caption back as a value unless `matchLabelRow` guards it; a staff cell may hold `Ime Prezime / Ime Prezime` and a trailing `(date)` note; rosters are pre-numbered with **blank slots mid-table**, so the parser must never stop at the first nameless row; the free-text column is `POVRATNA INFORMACIJA`. The `9. MJ.`…`6. MJ.` amount columns are deliberately ignored — an archived year imports fully settled.
- **`--inspect` prints structure only** — sheet classification, label rows, header captions, and masked value *shapes* (`9{2}.9{2}.9{4}.`), never a cell value. It exists because the workbook contains children's personal data and cannot be shared, so the importer was written against a described layout; `tests/integration/import-competition.test.ts` builds a synthetic .xlsx and **is** the layout specification.

## Testing — three tiers
Tests are split across three tiers by what they actually need to run; each newer tier is slower and exercises more of the stack.

- **Tier 1 — Unit** (`vitest`, jsdom env, `tests/unit/`): pure logic, Zod validators, component behavior. Lives under `tests/unit/{lib,validators,proxy,components}/`. No DB, no HTTP, no browser. Sub-10s feedback.
- **Tier 2 — Integration** (`vitest`, node env, `tests/integration/`): route handlers + Prisma against the dedicated `inovatic_test` Postgres DB. `auth()` from `@/lib/auth` is mocked via `tests/integration/setup.ts`; call `mockSession({ id, role, … })` in a test to inject a logged-in role. Direct-Prisma factories live in `tests/integration/helpers/factory.ts` (createTeacher/Student/Admin/Group/Module/ModuleSchedule/Enrollment/TeacherAssignment/Material/Location). The tier shares ONE database with no per-file cleanup, so a globally-unique fixed value (a course `slug` like `slr-2`) must go through `ensureCourse`, not `createCourse` — two files both creating it race on whichever runs second. `npm run test:integration` runs `scripts/reset-test-db.sh` first — every full run starts from an empty, fully-migrated baseline so stale state from past tests can never leak. Tests run serially (`fileParallelism: false`).
- **Tier 3 — E2E** (`@playwright/test`, `tests/phase{1,2,3}/`): real browser, real dev server, real DB. Keeps multi-step UI flows, hydration races, SEO/OG checks.

When adding tests: pure functions → unit; route handlers needing DB+auth → integration; anything that needs a browser → Playwright. `npm run lint:all` runs the unit tier as part of the pre-commit gate.

## Verzije i objave (`/release`, 2026-08-18)

**A push is silent unless a release was cut for it.** Most pushes are invisible to the
people using the app, so they mail nobody — that stays the default and the cheap path.
Declaring a version is a deliberate extra step, taken with `/release`
(`.claude/skills/release/SKILL.md`) before pushing.

- **The changelog is code.** `src/lib/releases.ts` holds an ordered `ReleaseNote[]`, newest
  first: version, date, one-sentence title, and **`sections` — the changes grouped by WHERE
  they live**, each `area` named the way the sidebar names it (Kalendar, Upiti, Dolazak,
  E-mail…) rather than the way the route is spelled. Staff use different halves of the app,
  so a teacher must be able to scan for Dolazak without reading past everyone else's changes.
  The section says where, so the sentence under it says what and never repeats the place.
  Grouping by **novo/poboljšano/ispravljeno stays banned** (removed 2026-08-19, before any
  release shipped): that taxonomy splits a single feature across two headings the moment it
  both adds and changes something, which is most of them — grouping by place is the opposite
  axis and reinforces the "say where it lives" rule instead. Its file header carries the
  writing rules and worked examples, and `tests/unit/lib/releases.test.ts` enforces them —
  including a guard that **rejects repository vocabulary** (file names, `prisma`, `commit`,
  `deploy`, backticks…) in the area headings as well as the lines, and an `isAreaLabel`
  predicate so a heading cannot silently become a sentence. Notes are in Croatian and name
  only what someone can see or do in the app; a refactor, a test, or a fix to a feature
  **shipping in the same release** gets no line at all — nobody ever had the broken version.
- **The database holds a receipt, not a copy.** `ReleaseAnnouncement.version` is the primary
  key and the claim: `src/lib/release-announce.ts` INSERTs it **before** the first mail, so a
  deploy, a crash restart (`restartPolicyMaxRetries = 3`) and two instances booting together
  all converge on exactly one send. Same claim-before-send ordering as
  `EmailCampaignRecipient.sentKey`, and for the same reason. Notes deliberately do **not**
  live in the row — a wording fix later can never disagree with what was actually sent.
- **The trigger is server start**, via `register()` in `src/instrumentation.ts` — Railway
  starts a fresh process per deploy, so the mail goes out seconds after the release is live,
  with no cron and no route to protect. It is fire-and-forget: an unreachable Resend must not
  hold up the healthcheck.
- **Recipients are `role: ADMIN, deletedAt: null`**, mailed at their real `User.email` (an
  admin signs in with it, unlike a student's synthetic address). No `city` — a release belongs
  to the application, not to an office, so it sends from the association address for both
  tenants. Template `emails/release-notes.tsx`, sender `sendReleaseNotesEmail`.
- **Three gates keep it off every non-production machine**, and the `RESEND_API_KEY` no-op is
  not one of them — `.env.local` on the dev machine holds a working key, so a dev boot would
  otherwise announce to the seeded admins. `instrumentation.ts` requires
  `NODE_ENV=production` and no `RELEASE_ANNOUNCE_DISABLED`; the announcer additionally
  returns **before claiming** when there is no key, because a receipt written locally would
  silence the real send forever.
- **Giving a claim back is allowed exactly once**: when `sentCount` stayed 0, nobody was
  reached and a retry cannot duplicate anything. Any partial success keeps the claim — one
  admin missing a note beats everyone else getting it twice. Releases older than
  `ANNOUNCE_WINDOW_DAYS` (30) are never announced, which is what stops a restored backup
  from mailing the whole changelog.
- The version is the same string in three places — `src/lib/releases.ts`, `package.json`,
  and the `v<version>` git tag. If they disagree, the changelog wins.
